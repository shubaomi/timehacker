## 1. 体验声明

- **产品目的**：把“秒表停在 `10.00`”变成轻量的页面解谜游戏。真正的乐趣来自发现页面中不协调的地方、推断隐藏规则并让时间出现可利用的破绽。
- **首要用户与任务**：首次进入的桌面或手机玩家，应在数秒内理解计时挑战，在不阅读长说明的情况下开始，并通过观察和试验发现当前关的谜题。
- **目标感受**：明亮、轻松、好奇、有一点淘气；破解时产生“原来页面本身就是规则”的顿悟，而不是完成考试题、后台任务或实验室指令。
- **核心记忆点**：整个页面是一张会被玩家修复、折叠、观察、遮盖、描画或改写的纸；秒表、边缘、文字、留白和浏览器状态都可能属于谜面。

核心循环固定为：

```text
看见不协调之处
→ 做出可推理的尝试并立即获得反馈
→ 破解页面规则，让时间进入辅助状态
→ 在 9.50 后明显减速，并在 10.00 保持
→ 轻松停在 10.00
→ 获得祝贺、分享图片卡片或继续下一关
```

## 2. 正式产品信息架构

### 2.1 首页首屏

正式首页继续采用已经确认的极简产品壳，不得复制 `/playtest-v2` 的工作台：

1. 左上品牌图标与 `TIME HACKER` 字标。
2. 右上菜单按钮；默认关闭。
3. 一句紧凑的 `10.00` 挑战文案；巨大挑战标题仅用于首次进入或第一关。
4. 当前关独有的整页纸上场景与谜题对象。
5. 秒表，只显示秒和两位小数。
6. 一个主要开始/停止/再次挑战按钮。
7. 停表后的简洁结果与图片分享入口。

首屏禁止出现：

- Gate B 标题、关卡切换器、状态评审按钮、interaction spike 或评审说明。
- 常驻关卡列表、作弊方法收藏、排行榜、设置、玩家数据或后台式导航。
- 实验室、操作员、UTC 频道、服务指令、任务步骤和仪式进度等虚构系统文案。
- 统一的星星、问号、闪光点或小图标作为所有关卡的发现入口。

### 2.2 右侧抽屉

所有次级与管理功能继续初始化隐藏在右侧菜单抽屉中，包括：

- 中文/英文切换。
- 作弊玩法与纯净计时模式。
- 已解锁的难度和关卡进度入口。
- 提示入口；提示属于玩家主动请求的渐进披露，不常驻首屏。
- 作弊方法收藏与全球排行。
- 玩家次数、成功数、最佳误差和剩余次数。
- 解锁后的昵称设置与需要二次确认的进度重置。

打开抽屉时保留当前游戏上下文；关闭后回到同一关。抽屉不能变成谜题说明页。若个别关卡临时利用菜单纸层作为谜面，也必须保留所有真实菜单功能和可访问路线。

## 3. 关卡状态与信息层级

生产状态语义为：

```text
DORMANT → DISCOVERED → SOLVING → ARMED → RUNNING_ASSISTED → RESULT
                         ↘ RUNNING_NORMAL → RESULT
```

- `DORMANT / DISCOVERED / SOLVING`：场景主导，玩家观察和实验；不显示步骤卡、进度数字或答案浮层。
- `ARMED`：以简短、非说明书式反馈确认作弊已经生效，场景开始收束。
- `RUNNING_NORMAL`：玩家没有破解也可以直接正常计时。
- `RUNNING_ASSISTED`：场景静止且不拦截停止按钮，秒表成为唯一视觉焦点。
- `RESULT`：显示两位小数结果、明确祝贺或鼓励、重试/下一关和图片分享，不显示开发诊断信息。

合理尝试必须在 `150ms` 内通过位移、材质、声音、纹理或轻震回应。错误可以软回退，但不能表现为“点击了没反应”。

## 4. 谜题与提示合同

- 每关只有一个主要异常和一条可推理的主要因果，不靠隐藏热区碰运气。
- 发现方式和破解方式都要由当前关的场景关系决定；差异不能只来自颜色、图标、文案或事件序列。
- 简单点击可以是自然操作的一部分，但不能成为 100 关重复的完整答案。
- 看起来可操作的物体必须可操作；纯装饰不得伪装成按钮。
- 首次提示只指出观察范围，第二级揭示关系，第三级才给出接近操作级的方向；任何提示都不直接播放完整答案。
- 中文和英文分别成立。依赖英文词义的关卡必须为中文玩家提供公平的语义线索，而不是要求猜语言考试答案。
- 摄像头、方向传感器、多指、切换页签等能力只能作为主动选择的增强路线；必须有完整的鼠标、触摸或键盘替代路线。

每关至多经历一轮文档审核、一轮交互原型、一轮 `3–5` 人未知答案盲测和一轮硬门修复。第二次仍失败同一硬门时，简化或替换，不无限调参。

## 5. 统一计时收益

所有成功破解的关卡采用同一种诚实、可感知的奖励：

1. 激活后正常前进到 `9.50`。
2. 从 `9.50` 起，每个真实秒只增加 `0.10` 显示秒，即依次显示 `9.50 / 9.60 / 9.70 / 9.80 / 9.90 / 10.00`。
3. `10.00` 至少保持 `3` 个真实秒。
4. 玩家仍需亲自按停止，系统不伪造自动命中。
5. 所有可见时间、结果和误差统一显示两位小数；数据库可以保存更高精度。

辅助状态必须通过节奏和画面让玩家感到“时间真的慢下来”，不能只扩大后台判定窗口。

## 6. 响应式构图

- **桌面**：利用页面四边、宽留白和物件之间的空间关系构成完整舞台；不扩展成仪表盘或多栏卡片页面。
- **手机与窄平板**：为 `360×800`、`390×844` 及 `681–820px` 宽的短视口重新裁切为纵向纸上舞台，不把桌面场景等比缩小，也不把关键物件塞进角落。
- **共同规则**：秒表、主按钮和谜题对象互不争抢；没有横向滚动、裁切核心线索或被安全区/浏览器边缘遮住且无法滚动到达的主要操作。短屏允许自然纵向滚动，但不得缩小机关、建立固定层内滚动或改变解谜输入。
- **100 关几何门**：涉及主舞台垂直位置、计时卡尺寸或 `681–1000px` 断点的修改，必须在 `1536×800 / 1440×900 / 734×876 / 590×698（中文，等价于 734×876 物理像素加 125% Windows 缩放）/ 390×844` 五个视口逐关检查专属机关根纸面与所有可操作元素。常规视口必须完整位于视口内；590×698 短屏可以位于可滚动文档内，但必须能够自然滚动至完整机关，并始终避开标题、计时器和主按钮。
- **内容极值**：中文和英文分别验收，允许自然重排；不得用强制 `nowrap` 掩盖构图问题。
- **物理设备**：自动手机视口只证明布局。拖放、多指、软键盘、摄像头和设备性能仍需真实手机检查。

## 7. 视觉系统

### 7.1 已批准方向：日光纸上剧场

- 页面是一张明亮的纸上舞台，不是中央白色秒表卡外加装饰背景。
- 保留深蓝品牌文字与数字、纸白、日光黄、珊瑚主按钮、薄荷和克制的紫色辅助色。
- 代表原型采用 `Bricolage Grotesque Variable` 作为主要拉丁字体，并以 `PingFang SC`、`Microsoft YaHei` 等中文系统字体回退；计时和少量编号可使用 `Azeret Mono Variable`。
- 每关通过轮廓、材质和空间拓扑形成辨识度：纸纤维、透明层、丝带、墨迹、折缝、地平线、回声、视口或负空间，而不是随机 pastel 圆斑。
- 每关最多一个主强调色、一个辅助色和一个循环环境动效；答案不能只依赖颜色或动画。
- `001` 的破损整页纸框、`003` 的漂动活版字牌、`100` 的明亮暮色星场是已批准的代表剪影。
- 终章允许从日光过渡到明亮暮色，但仍属于同一纸上产品，不改成黑色科幻实验室。

### 7.2 形状、层级与动效

- 品牌图标、字标、秒表数字和主要按钮保持产品一致；关卡舞台负责变化。
- 纸片可以圆润，但禁止所有内容统一套入相同圆角卡片、玻璃拟态或无意义阴影。
- 成功反馈短促、有成就感；普通过渡克制。
- 减少动态模式下移除循环位移和强变换，但通过形状、位置和纹理保留谜题线索。

## 8. 组件与实现边界

### 8.1 复用

- 复用正式首页的品牌、默认关闭的右侧抽屉、计时逻辑、结果、图片分享、双语、API、玩家进度和数据库身份。
- 复用已验证的统一辅助计时规则，但不能直接把 Gate B 的确定性展示计时当成生产计时器。
- 仅在经过架构审核后复用 `/playtest-v2` 中的识别器或场景代码；原型文件本身不是生产架构。

### 8.2 新建

- 公共关卡状态机和输入/反馈协议。
- 少量共享的纸面物理、轨迹、对齐、节奏、遮挡和视口能力。
- 对无法由公共能力忠实表达的关卡建立专用控制器，禁止把不同机制压成统一的“移动超过若干像素”。

### 8.3 禁止

- 统一三物件生成器、固定第一个物件发现/第二个物件破解的模板。
- 所有关卡共用同一秒表卡、发现图标、任务浮层或答案弹窗。
- 通过扩大不可见命中区、读取内部答案或只写 E2E 脚本来假装谜题可玩。
- 自动修改共享数据库、替换正式首页、加入生产导航、部署或公开 100 关。

## 9. 无障碍与质量门

- 所有真实控件具有语义名称、可见焦点和不小于约 `44×44px` 的实用触摸目标。
- 核心游戏可使用键盘完成；手势等价路线要保留相同因果，而不是“一键跳过”。
- 状态变化使用适当的 live region，不强制抢走焦点。
- 正文、控件、焦点和状态达到 WCAG AA；含义不只依赖颜色。
- 页面支持减少动态，并在 Edge、WebKit、桌面、手机视口和真实手机上检查。
- 应用自身控制台零错误；浏览器扩展错误与应用错误分开记录。

## 10. 参考与反参考

- 《帽子先生大冒险》：简单操作可以承载规则反转，关键是玩家能够从场景关系推断答案。

## 12. 2026-08-27 空间视觉试点附录

本附录不取消第 11 节的人类盲测门，而是在生产替换之前增加一个可完全关闭的技术与视觉试点，用来验证 ThreeUI 类空间构图能否与真实关卡规则融合，而不是成为无关背景。

- 试点关卡固定为 `001 four-corner-breach`、`002 breath-gap`、`008 relay-sandwich`、`043 archive-route`、`081 dual-device`；其余 95 关不进入正式视觉白名单。
- 空间层只能单向读取既有 `status`、`armed`、结果和关卡身份；不能调用 `onArm`、计时函数、判定、进度、API、数据库或分析发送函数。
- 正式 HTML 谜题对象可增加 `aria-hidden`、`pointer-events:none` 的深度结构；其按钮、命中区、键盘路径、阈值和测试 ID 不变。
- 运行后的时间场使用延迟加载 Canvas；Canvas 必须 `aria-hidden`、不可聚焦、不可接收指针，并位于计时、结果和主按钮下方。
- `idle / running / stopped / success / miss` 的运动只表达现有状态。停止操作仍先完成既有时间提交与服务端判定，视觉层随后读取 `STOPPING / SUCCESS / FAILED`。
- 001 的纸角必须被同一纸框吸收，不留游离副本；043 的光带端点必须与三页签共享坐标；081 的两半环必须共享中心和插口，完成接缝公差 `<=1px`。
- 002 在 2.5 秒前不得以光晕、空位或目标圆提前暴露气泡；008 必须由现有透明中层和左右 HTML 壳形成夹层，不能用新绘制圆覆盖或替代三件正式物件。
- 默认关闭；关闭后 DOM 交互、时间、判定、分数、进度、API 请求与分析事件必须与基线一致。
- reduced-motion 移除循环空间运动但保留完整状态与完成几何；WebKit 或移动性能不足时视觉层可降级或停用，玩法不得降级。

通过本试点只允许请求下一阶段批准，不自动授权扩展到 100 关或部署。

## 13. 2026-08-29 空间视觉 Batch A 扩展附录
