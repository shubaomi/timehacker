## 1. 查重定义

底层输入重复不等于玩法重复。只有“玩家先观察到什么、需要改变哪条规则、完成后形成什么关系”三者都不同，才算独立关卡。

矩阵使用以下七项识别重复：

1. `discovery`：最先让玩家意识到异常的页面关系。
2. `solve`：最终使规则成立的关系。
3. `input`：主要输入原语，不把 Pointer Events 当成创意。
4. `cognitive shift`：唯一主要“原来如此”。
5. `silhouette`：缩小成黑白剪影时仍能区分的构图。
6. `fallback`：移动端、键盘、权限拒绝和减少动态路线。
7. `risk`：必须由原型或盲测证明的点。

硬规则：同一 `discovery + solve + cognitive shift` 组合不得出现两次；同一主要输入不得连续出现超过三关；同章不得有两关同时复用相同剪影与完成反馈。

## 3. 分布审查

### 3.1 输入原语分布

| 输入族 | 设计数量（人工主类） | 使用边界 |
| --- | ---: | --- |
| 单物件拖动、移动或缩放 | 27 | 目标分别是修复、比较、改边界、移动光源或观察层，不得共用同一热区模板 |
| 多物件拖放或层级 | 19 | 每关最多三个主动物件；正确关系必须由材质、影子或纸边推理 |
| 翻页、折叠或旋转 | 19 | 采用离散档位与吸附，不做 3D 精细操控 |
| focus、hover、连续拖影 | 6 | 手机和键盘拥有同义路线，不能只依赖 hover |
| 等待、长按或宽时机窗口 | 8 | 不依赖后台时间，不重复等待，不做毫秒考试 |
| 节拍或相位 | 9 | 视觉路线完整，声音只增强 |
| 连续轨迹或边缘穿越 | 7 | 识别顺序、闭合或拓扑，不做像素模板 |
| 浏览器/设备状态 | 5 | 页面内正式路线优先，权限与真实 visibility 不唯一 |

数量按主要输入统计；一关可以包含一个辅助动作，但最多两种连续模式。分布值将在实现前由结构检查脚本从正式关卡 manifest 重新计算，本稿不是代码事实。

### 3.2 认知转变分布

- 页面结构与边界：18 关。
- 影子、焦点、观察层和遮挡：22 关。
- 文字、数字、符号与阅读规则：16 关。
- 时间、节拍、相位与距离转译：19 关。
- 共享中心、镜像、耦合和层级：17 关。
- 浏览器状态、输入来源和持久痕迹：8 关。

这些类别会复用系统词汇，但 100 行没有相同的发现、破解与认知转变三元组。
