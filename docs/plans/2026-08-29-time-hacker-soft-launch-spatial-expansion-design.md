## 2. 原始问题与结论

### 2.1 当前问题

桌面 1440px 与移动 390px 截图复核显示：九个机制均已存在并可见，但多数仍被阅读成“计时器下面或旁边的一块平面小组件”。它们与计时数字之间主要靠位置相邻，而不是靠空间因果相连；换背景、加环带或给整页增加景深无法解决这个问题。

移动端的问题更明显：计时卡占据主要视域，关卡物件被压到下半屏，003 字牌、014 十字、024 轨迹、067 轮盘等虽然完整，却缺少足够的立体轮廓和规则可读性。035、040、044、069、100 的纸板容器进一步强化了“卡片里的小游戏”，而不是“网页本身就是谜面”。

### 2.2 设计结论

九关不应获得同一套 3D 背景。每关的**原有可操作物**必须成为空间雕塑：

- 层级玩法用前后层、遮挡和投影表达；
- 路径玩法用轨道长度、穿层和交点表达；
- 延迟玩法用前后波面和材料滞后表达；
- 页面边界玩法用视口前后、纸张翻面和浏览器可见性表达；
- 负空间玩法用“空白的体积”表达。

语义 HTML 仍是唯一真实交互层。CSS 3D、SVG/Canvas2D 和可选 WebGL 叶节点只读取正式状态，不拥有完成条件、计时、判定、进度或分析写入能力。

## 3. 外部参考的采用与拒绝

用户提供的 ThreeUI 页面作为高层视觉参照：

- [Liquid Minutes](https://threeui.com/motion-design/liquid-minutes)：借鉴“时间像材料一样被压缩/冻结”的感觉，不复制布局、品牌或实现。
- [ThreeUI Rings](https://threeui.com/hero/threeui-rings)：借鉴嵌套深度与成功锁定，不把所有关卡变成圆环。
- [Ripple Study](https://threeui.com/text-animation/globe-study/ripple-study)：借鉴输入后的扰动传播与延迟回声，不把数字本身变成不可读的特效字。

ThreeUI 页面本次自动读取不可用，因此本文不声称知道其源码、精确着色器或内部结构。补充参考只用于验证技术边界：Codrops 的 Akaru 案例说明 DOM/CSS 正文与 WebGL 背景可以分层通信；水纹案例说明小尺寸 Canvas 纹理与后处理即可产生折射感，不需要完整流体模拟。

明确拒绝：暗色科技隧道、自由相机、跟随鼠标的整页流体、滚动劫持、自定义光标、模型展厅、持续粒子风暴、AI 紫色与大面积外发光。尤其不采纳按逐帧鼠标速度生成轨迹的做法，因为它会增加输入轨迹处理、移动端成本并弱化关卡自身的操作语义。

## 4. 统一空间架构

### 4.1 三层职责

| 层 | 职责 | 硬边界 |
|---|---|---|
| 语义玩法层 | 现有按钮、数字、可操作物、焦点与 live region | 唯一可交互、可聚焦、可决定玩法的层；测试 ID、事件名和命中区域不变 |
| 规则材质层 | 物件厚度、前后面、连接影、轨道、遮挡、折射壳 | 与真实 HTML 物件共用几何来源，只读状态；装饰节点 `aria-hidden`、`pointer-events:none` |
| 时间氛围层 | 低密度光线、空气透视、状态冻结与短促释放 | Canvas/可选 WebGL 延迟加载；不能遮挡数字/按钮，不能成为答案提示 |

### 4.2 3D 必须成立的判断

一关只有同时满足以下条件才算“空间融合”，否则视为背景换皮：

1. 移除通用时间场后，关卡物件本身仍有清楚的前后关系或体积。
2. 深度差能解释原规则中的层、顺序、路径、延迟、边界或负空间之一。
3. 玩家操作的仍是原 HTML 物件，视觉壳不会扩大、缩小或偏移正式命中区域。
4. 成功时是原有几何关系完成，不生成一个替代答案的重复物件。
5. 关闭视觉功能后，以相同输入序列得到完全相同的关卡状态、时间和结果。

### 4.3 状态映射

| 状态 | 九关共同表现 | 禁止事项 |
|---|---|---|
| `idle` | 只保留 1–2px/1–2deg 的材料呼吸或离散层差，数字完全稳定 | 不提前照亮正确目标、顺序或路径 |
| `running` | 时间场收紧；关卡物件只反馈玩家已经触发的正式关系 | 不随计时预测答案，不折射计时数字 |
| `stopped` | 正式停止、计时提交和判定先完成；视觉随后冻结上一帧 | 不用动画延迟判定，不伪造结果 |
| `success` | 150–450ms 的锁定/压印/折射释放；完成几何保留 | 不阻塞下一步，不复制已完成对象 |
| `miss` | 120–260ms 克制回弹；发现进度按正式规则保留 | 不增加惩罚、等待或重置正式状态 |

`discovery / solving / armed` 只作为正式控制器状态的视觉映射：视觉层不得自行推断或推进这些状态。

## 5. 推荐实施顺序

工程批次不改变玩家看到的冻结关卡顺序。每批使用精确 slug 白名单并默认关闭；前一批未通过视觉、规则等价、移动端、WebKit 和无障碍门时，不开始下一批。

### Batch A：可读物件深度（推荐先批准）

`003 slow-command`、`014 corner-cross`、`044 focus-orbit`

这三关分别验证“字模深度”“耦合平面”“光学焦面”。它们不依赖页面隐藏、传感器或长轨迹识别，能先建立可复用的 HTML/CSS 3D 物件壳、共享几何和只读视觉接口，风险最低且最能证明不是背景换皮。

**2026-08-29 实施状态**：三关已在默认关闭的精确 slug 白名单下完成本地实现；正式控件仍保持原命中几何，新增 DOM 均为 `aria-hidden` 且不可接收指针，Canvas 仍只读游戏状态。浏览器、响应式、reduced-motion 和视觉证据详见 [`2026-08-29-time-hacker-spatial-batch-a-003-014-044-implementation-spec.md`](2026-08-29-time-hacker-spatial-batch-a-003-014-044-implementation-spec.md)。本状态只表示“可供产品视觉验收”，不表示 Batch B/C、生产默认开启或部署已获批准。

### Batch B：时间拓扑

`024 precision-five`、`067 wheel-echo`、`069 archive-figure-eight`

这三关把时间编码在路径长度、回声延迟和两次交叉中。需要更严谨的 SVG/Canvas 坐标、连续输入和 reduced-motion 静态反馈，因此在 Batch A 的几何接口稳定后再做。

### Batch C：网页边界与终章

`035 horizon-shift`、`040 tab-return`、`100 silent-constellation`

这三关分别触及视口视差、页面可见性/BFCache 和可选摄像头。空间潜力最高，但浏览器与权限风险也最高，必须最后实施。相机仍是 100 关成功后的可选庆祝，不是主路径。

## 6. Batch A 逐关冻结

### TH-SX-003：003 `slow-command` / 可移动字模台

**正式规则不变**：四张字牌通过点击、纵向划动、滚轮或上下键逐格变化；一次机械遍历得到 `TIME` 但不完成，第二次得到 `SLOW` 后稳定 400ms 才完成。无文本框、提交按钮或软键盘。

**空间构图**：四张现有 HTML 字牌成为厚纸活字，沿同一横向排字槽分居四个 z 平面。错误字形在近景略微错层；第一次形成 `TIME` 时只短暂对齐但仍浮动；`SLOW` 才压入同一焦平面并留下共享珊瑚色长影。字面不倾斜到影响阅读。

**状态**：

| idle | running | stopped | success | miss |
|---|---|---|---|---|
| `FAST` 四块错层，缝隙透出淡黄纸光 | 玩家操作过的字块产生一次机械翻面；未操作块不暗示答案 | 保留当前字形与翻面角，随后读取判定 | `SLOW` 压入槽内，四块共享一条短影 | 只让最后一块回弹，不回到 `FAST` |

**响应式**：桌面将四块从侧边小组件放大为横跨计时卡下缘的排字台；390/360px 保持四列，不横向滚动，单块最小可操作宽度沿用正式值；590px 短屏允许排字台与计时卡视觉重叠，但不覆盖主按钮。reduced-motion 用正/背面离散切换和阴影深度代替翻转。

**技术边界**：CSS perspective + 伪元素/aria-hidden 侧边；不得用 WebGL。逐帧翻转值走 CSS/Motion value，不写 React state。

**验收**：一次四块遍历仍只得到 `TIME`；第二次得到 `SLOW` 并保持原 400ms；所有输入等价；字块正面在 WebKit 不出现镜像/消失；开关前后命中区域与完成时刻一致。

### TH-SX-014：014 `corner-cross` / 耦合纸带十字

**正式规则不变**：水平与垂直断带联动 35%；必须让两处切口同时进入共享 36px 中心吸附区，单轴不能完成。单指可交替移动，键盘路径保持有效。

**空间构图**：水平纸带在前层，垂直纸带从计时卡后层穿出；两者用一段仅作视觉的纸下联动铰链连接。移动任一真实 HTML 带时，视觉铰链展示另一轴 35% 的受力，中心不是虚线投放框，而是两张纸的自然切口。

**状态**：

| idle | running | stopped | success | miss |
|---|---|---|---|---|
| 两带分层、中心漏光，不描出目标框 | 已发生的 35% 联动以纸下张力影表现 | 冻结两轴当前位置 | 两条带在中心形成单一无接缝十字压印 | 保留位置，仅让未入区切口轻回弹 |

**响应式**：桌面十字可部分跨过计时卡边缘；移动端放大到约视口宽 70%，保持中心可达且不要求双指；平板不改变 35% 位移映射。reduced-motion 取消弹簧摆动，以连接影长度显示联动。

**技术边界**：真实 transform 继续属于现有玩法层；材质层只读取同一 CSS custom properties。不得对视觉倾斜后的 `getBoundingClientRect()` 重新定义命中区。

**验收**：仅水平或仅垂直永不完成；两轴原 36px 区域内完成；拖动、触控和键盘路径一致；success 两半没有可见缝、重复边或未对齐连接线；360px 无裁切。

### TH-SX-044：044 `focus-orbit` / 前置透镜与三焦面小数

**正式规则不变**：三个小数残影与独立透镜可见；点击轨道只有波纹，点击透镜或移动小于 16px 无效；真实拖动透镜后出现局部清晰，放入可见 44px 目标区才吸附完成；键盘箭头等价。

**空间构图**：三个残影位于计时卡内部三个浅焦面，透镜是真实 HTML 圆片并位于最前层。拖动时只在透镜覆盖范围内把残影折成单个清晰小数点；目标区仍可见但不发光。默认使用 CSS mask + Canvas2D 局部折射；只有这一路径无法达到清晰焦差时，才允许提交一个独立、延迟加载、默认关闭的 WebGL 光学叶节点供再次审批。

**状态**：

| idle | running | stopped | success | miss |
|---|---|---|---|---|
| 三残影有静态焦差，透镜前置但不指向目标 | 正式拖动后透镜下局部变清；轨道点击仅产生一次短波纹 | 冻结透镜和残影焦面 | 透镜、轨道和小数点共享光轴，残影合一 | 错误对象只产生一圈波纹，透镜不自动靠近目标 |

**响应式**：移动端将纸板容器去卡片化，让透镜与焦面直接跨在计时卡下缘；44px 目标与正式命中区不缩小。短屏不把透镜放到按钮下。reduced-motion 用清晰/模糊离散阶跃，不做轨道旋转或连续折射波。

**技术边界**：HTML 透镜保持焦点、拖动和键盘处理；Canvas `aria-hidden`、`pointer-events:none`。不得采集或分析逐帧输入轨迹。

**验收**：点击轨道、点击透镜、<16px 移动均不能完成；44px 正式目标区不受视觉 transform 影响；关掉折射层仍可完整完成；数字始终清楚、对比度不因透镜降低。

## 7. Batch B 逐关冻结

### TH-SX-024：024 `precision-five` / 路径即时间的纸轨

**正式规则不变**：先一次连续经过五个曲线点，再输入短—长—短—长节拍；短 420ms、长 720ms、容差 ±35%；五次等长 500ms 无效；键盘路径保持。

**空间构图**：五点不是悬浮按钮，而是同一条厚纸轨上的五枚铆点。轨道前后坡度编码“长/短”的材料距离，墨珠经过坡顶后才进入节拍层；成功后五点形成一根连续空间梁。

**状态**：idle 显示轨道高低但不写节拍答案；running 只锁定实际经过的点和有效拍；stopped 冻结墨珠；success 轨道压成连续梁；miss 仅错误节拍段回缩，立即可重试。

**关键边界**：视觉点的屏幕坐标必须从真实 SVG/HTML 点获得，再通过 SVG CTM inverse 映射；禁止用倾斜后 bounding box 的线性百分比推算命中。reduced-motion 保留高低纸纹和有效点压印，不移动墨珠。

**验收**：原连续轨迹、五点顺序、时值和容差完全一致；五个 500ms 仍失败；旋转/缩放/390px/360px 下可见铆点与真实命中点误差不超过现有测试容差。

### TH-SX-067：067 `wheel-echo` / 三层回声轮

**正式规则不变**：滚轮、局部划动或方向键只在谜面内转动；整页滚轮无效；四次移动让实体波到达缺口并消散，120ms 后对侧半透明回声补入；双方向都可，无顺序密码。

**空间构图**：实体波位于前层、纸轮位于中层、半透明回声位于后层。轮的厚度与切口让玩家看见“回声从背面回来”，不是在旁边画第二个圆。整页背景不跟随滚轮。

**状态**：idle 前后波面有静态材质差；running 每次有效局部输入只走一档；stopped 冻结当前档；success 后层回声穿入缺口；miss 实体波短暂散开但不增加延迟。

**技术边界**：120ms 正式计时源不移入视觉层；视觉回调可取消，切关/重试/离屏清除。reduced-motion 直接离散显示“前层消散 → 后层补入”，仍保留 120ms 正式逻辑。

**验收**：页面滚动不触发轮盘，轮盘输入不劫持谜面外滚动；四步、双方向、120ms 与现状相同；切关后旧回声不污染新关。

### TH-SX-069：069 `archive-figure-eight` / 双层连续印章

**正式规则不变**：一次连续笔划经过两瓣并穿过中心两次；左右起笔均可；分别画两个抬笔圆无效，错误中心摩擦/长路径无效；键盘路径保持。

**空间构图**：左右印章各在相邻薄纸层，中心是两层唯一共压点。连续墨迹第一次穿到背层、第二次返回前层；抬笔会留下两枚可见但未压合的半章，清楚表达“看似都画了但不连续”。

**状态**：idle 双瓣缺墨；running 已完成瓣保留且中心记录穿层次数；stopped 冻结当前墨迹；success 两层在中心压为一个完整章；miss 只让断口褪色，不抹掉正式保留的发现反馈。

**关键边界**：路径识别仍是原拓扑逻辑，不升级为像素级 8 字识别；视觉层从正式采样结果绘制，不把透视后的展示坐标回写控制器。reduced-motion 用前/后层颜色与线宽编码穿层。

**验收**：单连续笔划可完成，两个分离圆仍失败；左右起笔等价；中心必须两次；360px、触控和键盘下无视觉/命中漂移。

## 8. Batch C 逐关冻结

### TH-SX-035：035 `horizon-shift` / 三层纸景

**正式规则不变**：20px 视图移动产生三种不同视差；太阳与两条地平线进入视口高度 2% 的宽容区才完成；默认拖背景，键盘可完成，设备方向仅可选；拒绝权限仍可玩。

**空间构图**：前景、远景与倒影成为三张贯穿视口的纸幕，计时卡像开在纸幕上的窗口。拖动的是原页面视图，不是自由相机；深度只展示正式三层的不同速度。

**状态**：idle 三地平线近似但不重合；running 只响应正式视图位移；stopped 冻结视角；success 三幕共享单一地平线并短暂压平；miss 保留视角，不自动校正。

**技术边界**：不监听谜面外滚动，不用设备方向作为默认；视觉倾斜不改变 2% 计算。移动端降低视差幅度但保持正式 20px/2% 逻辑来源；reduced-motion 用三条离散高度线替代空间移动。

**验收**：权限拒绝、无传感器、键盘、触控均能完成；页面可正常滚动；三层视觉位置与正式高度源一致。

### TH-SX-040：040 `tab-return` / 穿过页面背面的票根

**正式规则不变**：直接抓取/向内拖会躲避；向外滑才发现页签切口；发现后 30 秒内必须发生 hidden→visible，或走等价的遮盖/揭开折页路径；初始 visible、发现前切换、超过 30 秒均不完成，超时不抹去发现；键盘 Enter 的遮盖路径同等正式。

**空间构图**：票根前半位于页面正面，发现页签后露出穿过视口边缘的背面。隐藏页面时不播放持续动画；回到可见后，票根从背层压回原纸痕。遮盖路线用一张真实 HTML 折页表达同一“去到背面再回来”的因果。

**状态**：idle 半票卡边且不提示外拖；running 只显示已发现的背面；stopped 冻结纸面；success 票根从背层回到压痕；miss/超时保留页签发现，不自动重启 30 秒窗。

**技术边界**：Page Visibility/BFCache/blur 由现有控制器负责；视觉层不得在隐藏期间推进动画或完成。切换标签、页面离屏和 inactive 时渲染暂停。

**验收**：所有前置/超时/遮盖/键盘合同保持；BFCache 恢复不重复完成；隐藏期间 Canvas/WebGL 为零持续帧；短屏无需滚到浏览器 UI 下方才能操作。

### TH-SX-100：100 `silent-constellation` / 有体积的负空间终章

**正式规则不变**：先聚拢两个可拖动三星组，显出负空间 V；再一次连续经过左上—底部—右上；任意点星、resize、随机线无效；键盘先聚拢、选三颗结构星并按住 V 700ms；相机手势仅为成功后的明确同意、3 秒超时、可清理的可选庆祝。

**空间构图**：六颗真实 HTML 星分居三层淡暮纸幕，聚拢后不是绘制一个答案 V，而是让中央空白形成可感知的棱柱腔体；只有玩家开始正式连续路径后，空腔边缘才被珊瑚色短光描出。成功时 V 形空白从纸面抬起一次后静止。

**状态**：idle 星群错层且不显答案；running 聚拢后负空间才获得体积，路径按正式进度点亮；stopped 冻结当前星位；success 空白 V 成为完成雕塑；miss 星群克制回弹，不遮挡立即重试。

**技术边界**：默认 CSS 3D + Canvas2D；如需真正体积光，仅允许一个 aria-hidden、pointer-events:none、延迟加载的 WebGL 叶节点，并在实施前单独提交性能证明。移动端禁用后处理、DPR≤1.5；reduced-motion/低性能直接使用静态三层纸幕。摄像头不进入空间层、不是默认路径、不影响结果。

**验收**：聚拢前不泄露 V；三个正式结构点与可见空腔边缘一致；resize/random/任意点星仍无效；键盘 700ms 路径完整；拒绝相机后仍为成功且无媒体轨道残留。

## 10. 提示与发现感

空间效果不是教程。初始状态不得出现“拖到这里”“先按哪块”“沿 V 走”等答案文字、虚线目标框、持续发光热点或唯一正确物件的强对比。

沿用正式渐进提示时序和语义：

1. 初始只展示材料差异与可操作性，不展示解法。
2. 长时间无有效发现后，只放大一个因果关系，例如“纸下有联动”或“前后层不同”，不直接说操作顺序。
3. 更晚提示才使用既有文案；视觉层不得自行计时或新增提示事件。
4. success/miss 的状态反馈可以明确，但不能回溯性地制造一个游戏里原本不存在的答案对象。

## 11. 性能、无障碍与生命周期

- 开始、停止、数字、结果和所有关卡操作继续使用语义 HTML。
- Canvas/WebGL 必须 `aria-hidden`、`pointer-events:none`，不进入焦点顺序。
- 正式停止处理先提交计时和判定，随后视觉层只读 `stopped/success/miss`。
- 不用 React state 保存逐帧鼠标、粒子、相机或动画值；使用 CSS custom properties、Motion values、Canvas 循环或隔离 client leaf。
- 视觉开关关闭、WebGL 初始化失败或 context lost 时，玩法、命中、计时和结果完全不变。
- Canvas/WebGL 延迟到首个空闲窗口或关卡稳定后加载；首屏 HTML 操作不等待视觉依赖。
- `document.hidden`、页面离屏、关卡 inactive、路由切换时立即暂停渲染并取消视觉回调。
- WebGL 只可能进入 044 的光学试验或 100 的体积光试验，且都需要单独批准；其他七关默认无 WebGL。
- 不增加摄像头、设备指纹、输入轨迹、逐帧鼠标速度或新的分析事件。

建议预算：CSS-only 关卡新增同步 JS≈0；Canvas 单关运行时目标≤1ms/frame（中位桌面）、移动端≤2ms/frame；WebGL 叶节点 gzip 增量与实际 GPU 帧时间必须在实施提案中实测，不在设计阶段虚报数值。

## 13. 风险、回滚与停止门

### 主要风险

- 3D transform 让可见位置与正式命中区域分离。
- 材料光、目标框或成功预演泄露作弊方式。
- 044/100 为追求“真 3D”引入过重 WebGL，反而降低首屏与移动体验。
- 040 在隐藏页继续动画或 BFCache 恢复后重复完成。
- 024/069 将展示坐标误写回轨迹识别。
- 035/067 劫持整页滚动。

### 回滚

每批精确 slug 白名单、默认关闭；关掉后不卸载或迁移任何玩法数据。视觉初始化失败直接退回现有页面。不存在数据库迁移、关卡数据迁移或玩家进度迁移。

### 批准门

1. 本文批准后，**只进入 Batch A 的默认关闭本地实现**。
2. Batch A 完成自动等价、五尺寸截图、WebKit/reduced-motion 和产品视觉批准后，才可请求 Batch B。
3. Batch B 通过后，才可请求 Batch C。
4. 044 WebGL、100 WebGL、035 设备方向与 100 相机庆祝均不是本文自动批准项。
5. 任一关出现规则偏移、答案泄露、命中漂移或短屏不可达，停止该批扩展；不得用改玩法来迁就视觉。

## 14. 明确推荐

推荐批准 **Batch A：003 + 014 + 044**。

它比先做最炫的 035/100 更适合作为下一步，不是因为视觉更保守，而是因为它能用最低的生命周期风险验证最关键命题：3D 是否真的长在规则上。003 的字模、014 的耦合纸带和 044 的透镜分别覆盖体积、层间受力与光学焦深；三关成功后，可复用的几何/材质接口再进入路径、延迟、页面边界和终章，既能显著提高高级感，也不需要先动计时、判定或关卡规则。

在产品负责人明确批准前，不修改正式游戏页面或空间白名单。
