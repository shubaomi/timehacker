## 目标、非目标与产品风险

- R100-01：玩家通过可见对象的关系提出假设、试验、修正，最后亲手停在 10.00；不能用强制点击序列、等待、记忆口令或隐藏命中区代替推理。
- R100-02：100 个既有 slug/数据库 ID 不增不删，所有成绩、解锁与匿名 ID 保留。已完成的关卡不强迫重玩。
- R100-03：每关都先有冻结的状态、输入、约束、目标、误解/反例、提示和验证规格，再进入正式实现。
- R100-04：操作清晰但解法不直给；首屏显示目标与实际连接关系，提示仍为主动请求。第三次请求可提供答案级方向但绝不代操作。
- R100-05：手机正常文档流，机关不能在计时卡下面或固定在屏幕之外；触摸/键盘相同离散操作，不引入精度和反应门槛。
- 不新增支付、广告、输入轨迹分析、摄像头、关卡数量、每日限制、自由相机或品牌改造。
- 风险：算术操作可能成为劳动，奇偶题可能成为盲点；不以 BFS 最短步数证明人类难度。不同章节使用不同状态空间和反例，而不是 100 次换数。尚无未知答案真人盲测，不声称留存、付费或商业效果已成立。

## 架构与边界

纯函数规则引擎负责状态转移和解决谓词。生产场景只是这一状态的语义 HTML 投影，按钮/键盘提交同一动作；渲染无权开始、停止或判分。求解器只用于离线可解性检查和开发验收，不在每次交互或首屏执行。撤销/重置免费，不记录操作轨迹到服务器。

生产适配沿用 V2_PUZZLE_DISCOVERED / V2_PUZZLE_ARMED、已有 API 与辅助计时。解开后锁定装置，进入已有开始/停止循环。未解开仍可纯速度挑战。推理不设 4 分钟过期门；版本 3 的触发只取消发现与完成之间的事件窗口，不改变时间算法。旧客户端事件、旧版本玩法仍可完成其进行中的一局。

用 `NEXT_PUBLIC_TIME_HACKER_REASONING_CAMPAIGN=1` 启用新主线；0 恢复旧主线。开发研究路由仍独立，旧四样本不覆盖。冻结 10.00、9.50 后的统一减速、10.00 三秒停留、容差、成绩和分享逻辑。

外观继承纸白/浅蓝/深蓝/珊瑚/日光黄及既有字体。不引入 WebGL 或资源下载，空间感由层次、前后连接和短促反馈产生。首屏为紧凑目标、机关、计时与唯一主操作；手机纵向自然滚动，桌面限制最大宽度。H0 无答案文字，错误显示约束原因，解开显示关系成立；reduced-motion 移除运动但保留变化前后数值与纹理。

## 数据迁移与回滚

优先不改表结构：新规则不需要新玩家字段。目录同步只按 slug 更新名称/描述/提示/学习难度及 triggerConfig 中的版本标记，保留主键与外键。不可更新或删除 User、GameRecord、UserCheat、PlaytestEvent 的历史行。

发布前：核实服务器源码/运行目录/环境，保存当前代码 SHA 与可恢复运行包；使用服务端 pg_dump 做备份并用 pg_restore --list 验证。备份不上传、不打印连接串。先部署测试构建，目录迁移前保存旧目录快照。失败恢复旧运行包、旧环境开关和旧目录；玩家新增记录不回滚。不得用全库恢复覆盖发布期间真实游玩。

数据库验证用只读目录比对、计数和约束检查。写入型集成测试只能使用单独隔离库/明确测试身份，不允许共享生产数据库的清表测试。当前已核实共享连接为生产库，目录 100 条、玩家 78、记录 19、解锁 5、事件 66；这些是发布前快照，不作为之后必须相等的绝对计数，因为真实流量可能变化。
